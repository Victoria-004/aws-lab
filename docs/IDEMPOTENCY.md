# Ідемпотентність операцій запису

## Яку проблему це розв'язує

Клієнт надіслав `POST /districts`, але не отримав відповіді: обірвалося з'єднання, спрацював тайм-аут або балансувальник повернув 502. Клієнт не знає, чи запис створено. Якщо він повторить запит, у базі може з'явитися два однакові райони. Якщо не повторить — запис може загубитися.

Заголовок `Idempotency-Key` робить повтор безпечним. Клієнт генерує унікальний ключ (наприклад, UUID) для однієї логічної операції і надсилає його з кожною спробою. Сервіс виконує операцію лише один раз, а на повтори повертає ту саму відповідь.

## Як це працює

Реалізація — декоратор `idempotent` у `app/my_project/utils/idempotency.py`, застосований до `POST /districts`.

1. Сервіс бере ключ із заголовка і рахує хеш тіла запиту.
2. Командою `SET NX` записує в Redis `idem:POST:/districts:<ключ>` зі станом `processing` і терміном дії 24 години. `SET NX` атомарна, тому з двох одночасних запитів ключ займе лише один.
3. Той, хто зайняв ключ, виконує операцію і зберігає в Redis код відповіді та її тіло. Якщо сталася помилка сервера (5xx), ключ видаляється, щоб клієнт міг повторити.
4. Повторний запит із тим самим ключем:
   - якщо операція завершена — отримує збережену відповідь із заголовком `Idempotent-Replayed: true`, а база не змінюється;
   - якщо операція ще виконується — отримує `409 Conflict`;
   - якщо тіло запиту інше — отримує `422`, бо той самий ключ не можна використовувати для іншої операції.

Запит без заголовка обробляється як раніше.

## Перевірка тестом

`tests/test_idempotency.py`:

- два однакові запити з одним ключем → обидва `201`, однакові тіла відповідей, у базі один запис;
- той самий ключ з іншим тілом → `422`, у базі один запис;
- два запити без ключа → два записи (для порівняння).

```powershell
$env:BASE_URL = "http://labdatabase-alb-470200426.eu-north-1.elb.amazonaws.com"
pytest tests/test_idempotency.py -v
```

Тест триває понад 2 хвилини, бо список `GET /districts` кешується на 45 с (див. [CACHE.md](CACHE.md)). Перед кожним підрахунком записів тест чекає, поки кеш спливе. Перша версія тесту цього не робила: вона створювала район і одразу читала список з кешу, де нового запису ще не було, тому падала.

## Обмеження

- Якщо Redis недоступний, сервіс виконує запит без перевірки ключа. Ми обрали доступність сервісу, а не гарантію від дублікатів.
- Ключ живе 24 години. Повтор через добу буде виконано як нову операцію.

## Зв'язок із чергою (завдання 6)

Черги доставляють повідомлення «щонайменше один раз»: обробник може отримати те саме повідомлення двічі, наприклад якщо він впав після запису в базу, але до підтвердження повідомлення. Якщо разом із повідомленням передавати `Idempotency-Key`, обробник перевірить ключ у Redis і пропустить повтор. Так поєднання «черга + ідемпотентність» дає ефект «рівно один раз» для бізнес-операції.
